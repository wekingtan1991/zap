裁决口径：
- **采纳** = 真需求、不违拍板、ROI 成立、无与既有入口重叠，按原案（或合并案）执行。
- **降级** = 需求方向成立但当前不该投入（改期 / 缩围 / 缺触发条件）。
- **改写** = 问题诊断对、原方案错或过重，换更小的实现。
- **驳回** = 伪需求 / 触碰拍板禁区且论证不足 / 与既有能力重叠到不构成增量。

## 2. 重点对抗项的深入裁决

### 对抗 1 · 行内计算器（R6 P1-4）vs 行内算式+单位换算（R10 提案1）：两个角色独立收敛，真的该做吗？

**骨架现状核验（两报告的事实基础全部成立）：**
- probe 骨架存在且已服务两个消费者：`probe_all`（`src-tauri/src/providers/mod.rs:583-592`）逐插件跑 `probe`，识别条目在 `search()` 中先于常规结果返回（`mod.rs:508`）；现有消费者 texttools（`texttools.rs:114`，识别时间戳/UUID/Base64/URL 编码）与 jsontools（`jsontools.rs:105`）。
- 「体验断裂」确凿：`web.rs:4-46` 对任何 query 恒产出（URL 直达 + 百度/必应/谷歌三条），`mod.rs:510-515` 注释自己写明「网页兜底恒有产出，不足为有结果的凭据」。输入 `128*0.75` → probe 无命中 → web 兜底 → Enter 打开百度搜「128*0.75」。
- **用「用户现在怎么活的」检验**：想在面板里算数的用户，现状是被主动推去浏览器（最差路径）或自己想起「zap 不算数」切系统计算器（次差路径）。新方案把路径缩为「呼出→输入→Enter=复制结果」。这不是伪需求——它不新增记忆键（probe 自动触发）、不新增 UI 面（就是一个 kind 条目）、不触碰任何拍板（确定性字符串解析，无模型无网络）。
- **两个角色该合并立项**：R6 只提四则/百分比（一天级），R10 补单位换算/时间差（再加两天）并给出误识别准入规则（「含运算符才算」）与 kind 注册陷阱提醒（未注册 kind 落 `dispatch.ts` external）。合并版以 R6 的 v1 为切片、R10 的工程细节为施工图。

**怀疑后的定级：采纳，且是 round2 全部功能类提案中优先级最高的一条。** 理由：zap 现有功能都在「处理已经拿到的东西」（剪贴板/文件/账号），唯独输入框的第一高频用途「算一下」被主动送出门外。单位换算降为 v2——它的语法形态（`100 km 到 mi`）与误识别面独立，不应拖慢 v1。

### 对抗 2 · R10 九条创新提案逐条过

- **提案 1（算式/单位）**：见对抗 1，采纳（合并版）。
- **提案 2（URL/文本清洗）**：场景真（微信/知乎/掘金链接的 utm/spm 污染是日常），实现完全搭 texttools 顺风车——`recognize` 已有 is_timestamp/is_uuid/is_base64 判定模式（`texttools.rs:137-244`），detect 内联答案有测试锁定（`texttools.rs:471`）。R10 对「清洗表永远清不完」的诚实值得肯定：v1 范围锁 `utm_*` 通配 + 高频国内参数，且**优先内联答案**（复制即走），工作台按钮随批。采纳。
- **提案 3（此刻预测）**：**降级，整条挂起，连埋点也不做**。理由：①R10 诚实清单自认「时间节律存在且可利用」零数据支撑；②它动的是空面板 top4（`mod.rs:500` `top_launch_items(4)`）——用户对这个槽位的顺序记忆最强，「预测错了抢走熟悉顺序」的信任代价 R10 有认识但低估；③「先埋点 3 个月」在无消费逻辑时是纯负债：一张新表、一条写入路径、零用户价值，正是单人维护产能最不该买的东西。挂起条件：出现真实用户反馈「空面板顺序不懂我」（issue 或自用体验），届时 R10 的「观测不足回退 + 只做加法槽位」双闸门设计可直接复活。产品判断，非证明方向无价值。
- **提案 4（窗口贴靠）**：**降级改期**。功能本体成立：右键动作模式现成（`registry.tsx:98-102` win 已有「关闭窗口」ctxAction；`App.tsx:426-433` allow map 按 kind 限权；`sysutil.rs:116-124` close_window 展示了同构的 WinAPI 封装模式），全鼠标零组合键不违拍板。降级理由：①「Aero Snap 需要记忆组合键」的论证强度一般——Win+方向键是系统级肌肉记忆，R10「不少人不用」无数据；②zap 心智是「搜索→启动」，贴靠是第一步外溢，应在核心缺口（计算器/清洗/诊断/更新收尾）清完之后再做；③DPI/最大化恢复语义要真机收口（R10 自认）。不否决。
- **提案 5（深链协议）**：**降级 12 个月+**。产品怀疑点：协议的第一个消费者是谁？「用户自己的 AHK 脚本」在 zap 目标画像内成立，但 zap 当前没有文档站、没有社区、没有插件页来**教**这个协议——无人知晓的协议入口等于不存在，而安全三闸（长度上限/动词白名单/默认关）都要真金白银写和测。`toggle_panel` 的 preset 参数现成（`lib.rs:1460`，注释确认预填语义）使实现确实便宜，但便宜不等于该做。触发条件：出现第一个真实集成需求。
- **提案 6（片段模板库）**：**降级 12 个月**。R10 自评「v1 与固定剪贴板+改名高度重叠、价值增量有限」——这个自我否定是对的，本怀疑者验证后完全同意：固定条目（`clipboard.rs:494-512` pin_toggle）已覆盖「顺手的暂存」。价值点在 v2 占位符填充（文本展开器品类，竞品验证过），维持 R10 的「v1/v2 绑定立项、防半成品」建议。
- **提案 7（数据插件包）**：**降级 12 个月**。前提「社区分享配置包」在 zap 没有社区时不存在。可独立成立的一半是「分段导入预览」（换机导入不全量覆盖，UX 先例在 vault 恢复预览 `mod.rs:465-480`），签名体系 R10 自己挂 36 个月，砍。
- **提案 8（带负载启动）**：**驳回，维持拍板**。R10 的翻案论证（三原语封闭、无 shell、无脚本语言）在工程上成立，但产品上翻不动：①拍板砍「快捷命令」的深层理由是**编排类能力的维护面失控**，而本提案的核心风险恰是「注入时序」——R10 自评「中-高」，需要「等窗口可输入」的轮询，这正是简报点名的三次收口所在的脆弱区（轮询/时序类）；②用户价值被高估：「开会并贴链接」现状 = 复制链接→点会议应用→Ctrl+V，本提案省的只是最后一次 Ctrl+V，却要引入新存储格式（appconfig JSON 动作链）+设置编辑器+时序执行器三个维护面；③R10 自己给了退路（「若论证不足应整体放弃，场景由提案 5 深链承接」）——采纳该退路。
- **提案 9（局域网接力）**：**驳回（不进入路线图）**。场景真（手机验证码→PC）、竞品验证过（LocalSend/KDE Connect）、不触碰「本地优先」拍板（反而是其延伸）。驳回理由是产能与安全面：这是九条中唯一开网络端口的提案，「v1 两周」的估工对 HTTP listener + 静态页 + 二维码 + token 轮换 + NetworkCategory 判定 + 手机浏览器权限矩阵而言显著偏乐观；它被 R10 放在 36 个月层本身就是诚实的信号。36 个月后若立项，v1 文本单向 + 默认关 + 公开网络拒绝启动三闸是底线（R10 已写明，予以保留）。
- **不推荐区四条（语义 embedding / 动态插件 / 宏录制 / 前台轮询）**：数值化重启条件的写法是本轮最佳实践，全部维持。

### 对抗 3 · 分发信任断层（R6 P0-1）+ 无签名缓解（R9 P1-1）：合并成什么行动

事实核验：`tauri.conf.json:62-64` 仅 `targets: ["nsis"]`、无任何签名配置；`release-notes.md:3-4` 自认未签名；全仓无 winget/scoop 清单；R9 的高启发式行为特征清单（SendInput `superpanel.rs:157`/`winsys.rs:201`、DPAPI `dpapi.rs:34/76`、剪贴板常驻监听、HKCU Run 自启 `lib.rs:1998-2004`、下载 zip 提权执行 `everything.rs:82-86`）逐条属实。

**合并裁决为一条「分发可信」专项，四步序：**
1. **本周可做（零成本）**：release.yml 附安装包 SHA256 + 向微软提交「可能被错误检测」分析（R9 建议 1/2）。
2. **一次 PR（零成本）**：winget 社区清单（R6 建议①）——采纳。注意 winget 不消除 SmartScreen（用户下载的仍是同一 exe），它的价值在可信渠道、版本管理与「正经软件」的叙事。
3. **一次调研（半天）**：签名证书渠道现状核清（Certum/SignPath Foundation/Azure Trusted Signing，R9 建议 3）。
4. **1.0 门槛项**：签名落地（R6 的 1.0 框架正确）。

**portable zip 驳回（R6 建议②）**：Tauri 主体自包含但 WebView2 依赖引导（R6 自评「成本中等」），便携版意味着第二支持面（WebView2 缺失机器的「双击没反应」工单）、每个版本多一份产物要测试与附签名。在国内绿软社区接入价值未验证前，这笔维护面开销不划算；winget 验证有效后再议。**降级（改期）**而非永久否决。

### 对抗 4 · 首启引导缺失（R6 P0-2）vs「空面板即功能首页」既有设计：真缺引导，还是设计被低估？

**核验结果：问题成立，且比 R6 写的更严重——但 R6 的方案之一（欢迎条）过重。**

先承认既有设计确实兜住了大部分可发现性（R6 也承认）：
- 空面板恒有内容：`assemble_opening`（`mod.rs:687-704`，最新剪贴板识别 + 最近 5 条）+ `top_launch_items(4)`（`mod.rs:500`）+ `fallback_all`（`mod.rs:503`，插件入口清单）——新用户呼出必见 JSON/文本工具/中转站入口；
- pw 靠 footer 常驻提示（`App.tsx:1454-1455`）撑住，问号悬停覆盖 Alt 组合键（`App.tsx:1389-1413`）。

**但「按什么呼出」这个唯一致命信息，产品内零露出——这里 R6 有事实错误**：R6 称呼出热键「唯一在产品内的露出是设置页与底栏」。本怀疑者核验了面板全部 UI：footer 左区（`App.tsx:1374-1498`：↑↓/Enter/合并粘贴/pw/Ctrl+V 粘贴即识别/json·tool/问号）、右区（`1500-1508`：Ctrl+, 设置 / Esc 清空/关闭）、空态文案（`1258-1280`：pw/右键/Ctrl+,）**均无呼出热键**；托盘 tooltip 是「zap — 个人效率入口」（`lib.rs:1967`），托盘菜单五项（`lib.rs:1928-1960`：显示面板/设置/剪贴板开关/自启/退出）也无。即呼出热键的唯一露出是设置页（进入面板之后才可见）——而进入面板的前提恰恰是知道呼出键。引导断裂确凿。托盘左键单击=呼出面板（`lib.rs:1927` 注释）和「二次启动=呼出面板」（`lib.rs:1634-1636`）是两条没人告诉用户的备用通道。

**热键失败态核验**：呼出热键注册失败仅 `eprintln!`（`lib.rs:1854`「仅可通过托盘呼出面板」），直达热键同样（`lib.rs:1884`）——release 下即无声。全仓 `onboard|welcome|first_run|首次|引导` 零命中（本怀疑者复核）。R6 P0-2 成立。

**裁决（改写）——保留诊断，替换方案：**
- **采纳**：首启自动呼出一次面板（首启判定：settings 无 `first_run_done` 键）。这是「空面板即首页」设计缺失的触发器，成本一次 `toggle_panel` 调用 + 一个设置位。
- **采纳（并升级为主方案）**：托盘 tooltip 动态化——正常时「zap — Ctrl+Alt+Space 呼出」，注册失败时「热键被占用：左键点此呼出，右键进设置修改」。托盘是装完后的自然第二触点（R6 自认），tooltip 是零交互、零状态机、常驻可见的信息面，比「出现 3 次的一次性欢迎条」承载同一信息而成本低一个量级。
- **驳回：欢迎条**。空面板兜底入口 + footer + 问号悬停已覆盖 pw/右键/设置/合并粘贴的露出，欢迎条新增的信息只有呼出键，而 tooltip 已传达；为它引入「出现 N 次后落位」的前端状态机 + 设置位 + 视觉设计，在单人维护产能下不划算。R6-P2-7（超级面板露出）同理并入：设置页文案层面提一句「选中文字按直达热键呼出动作菜单」即可，不做卡片。
- **采纳**：热键失败 `eprintln`→`diag::log`（与 #14 合并）。
- **采纳 R6 P2-8**：空态死文案（`App.tsx:1277`）直接删除——footer 已常驻 pw 提示，同一信息写两遍其中一遍永不渲染。

### 对抗 5 · R7 三条的产品定级与修法

**R7 P0-1（Ctrl+V 错位）——维持 P0，采纳修法，补一个实现注意点。** 核验：空态文案「按 Ctrl+V 粘贴，或点右上『粘贴替换』」（`JsonWorkbench.tsx:204-213`），而 window paste 监听仅在 `awaitPaste===true` 时挂载（`panel.tsx:52-53`），`awaitPaste` 唯一置真点是「粘贴替换」按钮（`JsonWorkbench.tsx:156-161` `startAwait`）——文案里的并列选项实际是唯一通路，新用户按提示操作第一次必然哑火。定级 P0 的产品理由：这不是深路径角落，而是「入口词进入」的默认落点 + 第一条引导文案为假。修法采纳「监听常驻 + 按钮降级为等待指示」；**注意点**：常驻后 `useAwaitPaste` 的 5 秒超时语义（`panel.tsx:62`）需要重新设计（等待态指示才需要超时，常驻监听不需要），别机械保留。

**R7 P1-2（设置双生效模型 + Esc 丢脏态）——维持 P1，采纳方案①。** 核验：`SettingsView.tsx:499-513` Esc 直接 `onClose()` 无脏态判断；延迟保存项依赖 `saveSettings`（530-583）+ 底部保存按钮；外观/透明即时生效。产品裁决取方案①（脏标记 + Esc 确认条，复用 zap-dialog）而非方案②（全即时保存）：热键录制与捷径编辑天然产生「半成品」（冲突检测、多行整单校验 `shortcuts_save`），即时落盘会把半成品写进存档——R7 的推荐正确。保存按钮禁用态一并采纳。

**R7 P1-3（vault 死右键 / 网址无鼠标打开）——维持 P1，采纳修法。** 核验：`registry.tsx` 中 app/clip/clipimg/file/recent/win/web/url 八个 kind 全部有 `ctxActions`，**唯独 vault 没有**（`registry.tsx:114-121`），右键只压默认菜单（`App.tsx:1291-1297`）即死右键；详情页网址行只有复制按钮（`VaultDetailView.tsx:197-233`），「打开网址」唯一入口是 Alt+1（`App.tsx:1070`）。产品定级补充：vault 是 zap 最敏感的功能面，用户对它的交互一致性最挑剔——「右键没反应」在这里的信任代价高于任何其他列表。修法照单（ctxActions 五项 + 详情页「打开」按钮，全部复用既有命令与渲染机制）。

**顺带核验通过**：合并模式 footer 右区「Esc 清空 / 关闭」失真（`App.tsx:1500-1508` 无条件渲染，而合并态 Esc 实为退出合并）属实，一行三元修复采纳；R7 P2-10 的「复制即走可能属刻意拍板」顾虑维持其诚实清单处理（自动粘贴关闭时改不收面板的折中可取）。

### 对抗 6 · 诊断导出/日志入口（R6 P1-3 / R9 P1-3 / R5 建议3 三方收敛）：产品化成什么形态

三方方案：R6「设置加打开数据文件夹按钮」；R9「设置页『关于』区加『打开日志文件夹』」；R5「日志收口到能回答四问」。

**裁决：形态 = 设置页新增「关于」区**（版本号 + 打开数据文件夹 + 查看日志说明），理由见新发现 1——round1 没有人注意到设置页根本没有「关于」区，SECURITY.md:14 的引用是悬空的。形态排除两项：**托盘菜单加诊断项**（托盘是高频操作面，诊断是低频需求，塞入只增密度）；**「一键导出诊断 zip」**（日志实况仅 zap.log 40KB + capture.log 25KB，R8 实测——explorer 打开文件夹让用户自己挑文件更诚实，实现只是一条 opener 命令，不引入打包逻辑这个新的维护面）。配套三件（panic hook 落 diag、启动期 eprintln→diag、bug 模板加日志路径）三方论证一致，全部采纳，合一个 PR。

## 3. 怀疑者新发现（round1 无人提出，均经代码核实）

### 新发现 1 · 设置页没有「关于」区：产品身份三要素（版本/数据位置/诊断）无家可归（结构性缺口）

- **证据**：SECURITY.md:14 让漏洞报告者引用「`设置 → 关于`」取版本号——该分区不存在（分区实测：启动/剪贴板/中转站/账号库/外观/备份/配置/搜索/Everything/搜索捷径/插件/更新；版本号寄居「软件更新」区）。R6 P2-10 把它当文档漂移报了，R9 在建议里默认「关于」区存在——**两人都没有看到这是个结构性缺口**。
- **为什么是产品问题**：①安全报告流程的第一步（取版本号）在产品内走不通；②诊断出口（对抗 6）没有自然的安放位置；③1.0 叙事（版本、门槛进度）需要一个正式的家。
- **建议**：设置页新增「关于」区：版本号（替代 SECURITY.md 悬空引用的真实落点）+「打开数据文件夹」按钮 + 「反馈问题请附 `%APPDATA%\com.ais.zap\zap.log`」一行说明。一个分区承载三个 round1 提案。

### 新发现 2 · Everything 数据源健康状态对用户零可见：文件搜索静默死亡时用户无法自助

- **证据**：后端已有 `everything_status` 命令（`lib.rs:118-123`），前端唯一消费是「Everything 未运行时在面板注入启用条目」（`App.tsx:304-310` `cmd:everything`）；设置页 Everything 区只有「自动启动」开关（`SettingsView.tsx:1026-1053`），无任何状态显示。而文件源的失败是静默的：端口探测可被任意本地 HTTP 服务劫持后永不自愈（`files.rs:32-48`，R5 P2-1）、查询失败仅 `mark_failed`（`files.rs:96`）——用户视角是「文件搜不到」，无法区分「Everything 没跑 / 端口被占 / 插件被停用」。
- **为什么 round1 漏了**：R5 P2-1/P1-3 从工程侧报了日志与自愈缺口，R6 从分发侧看了 Everything 下载信任，但「**用户可见的状态反馈**」这个产品面没人提。
- **建议**：设置页 Everything 区加一行状态（复用现成 `everything_status` 命令，零新后端）：「已连接 · 端口 xxxx」/「未检测到 Everything」+（可选）失败时的「重新检测」按钮。低成本补齐「唯一依赖外部进程的数据源」的可诊断性。

（候选第三条「关闭剪贴板记录开关的语义不含存量数据处置」经权衡并入总表 #34 作为产品强化，不单列——它与 R8 P1-1 同根，单列会重复计数。）

## 4. 诚实清单

- **「计算器是竞品标配」未逐一安装验证**：采信 R6/R10 独立收敛 + 品类常识（产品判断）；「输入算式 → Enter 开百度」的链路经 web.rs 核验成立，但「用户实际会往启动器里输算式」的频率无数据。
- **呼出热键零露出的核验覆盖面**：面板 footer/空态/托盘 tooltip/托盘菜单逐段读过；未读的只有设置页内部（热键在设置页可见这一点两份报告一致，采信）。R6 原文「露出是设置页与底栏」与本次核验矛盾，以核验为准。
- **欢迎条的驳回是产品判断**（信息可由 tooltip 等价承载 + 状态机成本），未做任何用户测试；若实测发现托盘触达率低，欢迎条方案可重新考虑。
- **portable zip 的驳回**基于 WebView2 引导支持面推断，未实装验证便携包的实际缺省行为。
- **「此刻预测」的挂起是 YAGNI 判断**，不是对该方向的证伪；R10 的双闸门设计质量本身予以认可。
