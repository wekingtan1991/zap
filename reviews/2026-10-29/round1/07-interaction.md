## 1. 角色结论摘要（≤5 条）

1. **交互纪律执行度整体很高**：Esc 渐进退出（有词清词→空了收面板）全链路一致；焦点丢失致 Esc 失效的坑已系统性收口（useEscCapture 窗口捕获 + focusPanelRef，`src/hooks/useEscCapture.ts:8`、`src/App.tsx:181`）；IME 卫兵覆盖到合并模式/中转站；发现性基本不靠背键（footer 常驻提示 + 问号悬停 + 右键菜单三件套）。
2. **唯一 P0 是文案与接线的错位而非模式缺陷**：JSON/文本工具空态教用户「按 Ctrl+V 粘贴」，但粘贴监听只在点过「粘贴替换」之后才挂载——新用户按提示操作第一次就哑火；修复不需要任何新键，把监听常驻即可（见发现 1）。
3. **设置页是交互上最薄弱的一环**：「部分项即时生效（外观/透明）、其余按『保存』生效」的双模型没有脏态保护，Esc 直接退出并静默丢弃全部未保存修改（见发现 2）。
4. **账号库键盘面齐备（Alt+1~6，悬停问号有说明）但鼠标面有实质缺口**：vault 行右键菜单为空、网址没有鼠标「打开」路径——与「其余鼠标」的等价性要求有差距（见发现 3）。
5. **反馈语义总体清楚**：错误文案全链路中文人话（后端 map_err 全带中文前缀，如 `providers/backup.rs:110`「不是 zap 备份文件」、`providers/stage.rs:84`「路径不存在：{p}」，抽样见诚实清单）；toast / 条内反馈 / 行内 ✓ / 落区条内文案四级反馈各司其职，跨窗口（落区条/超级面板）toast 不可见的问题有专门设计规避。i18n 现状确认：**无资源表、无 i18n 库（package.json:33-56 无任何 i18n 依赖），UI 文案全量写死中文，前后端皆然。**

## 2. 发现清单（≤10 条，P0 > P1 > P2）

### P0-1 JSON/文本工具空态「按 Ctrl+V 粘贴」在未点「粘贴替换」前无效——新用户主路径第一次就哑火

- **证据**：
  - `src/plugins/json/JsonWorkbench.tsx:204-213`：空态文案 `text !== undefined ? "按 Ctrl+V 粘贴，或点右上「粘贴替换」" : "正在读取剪贴板…"`；
  - `src/plugins/panel.tsx:50-70`：`useAwaitPaste` 的 window paste 监听**仅在 `awaitPaste === true` 时挂载**，而 `awaitPaste` 只能由点击「粘贴替换」按钮（`startAwait`，JsonWorkbench.tsx:156-161）置真；
  - `src/plugins/text/ToolWorkbench.tsx:332-338`：同样文案同样缺陷（同构复用）。
- **用户场景与后果**：用户从搜索入口点「json 工具」（`src/plugins/dispatch.ts` 路由到 `openJson`，target="entry" → source 为 empty）→ 面板显示空态提示 → 按提示按 Ctrl+V → **无任何反应**（监听未挂载、页面无可编辑元素）。用户会先怀疑自己复制错了，重试、换鼠标点按钮才能恢复；「或点右上」的补救在文案上是并列关系，实际是唯一通路。工具面板是产品三条获取路径（入口词/识别/剪贴板）里「入口词进入」的默认落点，第一印象即失败。
- **具体建议与权衡**：把 paste 监听改为常驻（面板挂载期间 window 捕获监听 paste，见 `panel.tsx:47` 注释已确认非可编辑焦点下事件可达）——空内容时收到粘贴直接填入；「粘贴替换」按钮保留但降级为状态指示（等待时显示「按 Ctrl+V 粘贴…」）。代价：粘贴目标语义变化（现在任何粘贴都会替换全文而非插入），对这两个只读展示型工作台反而更正确——它们本来就没有可编辑的输入区。完全符合「不新增记忆组合键」：Ctrl+V 是系统通用粘贴，不是需记忆的组合。
- **置信度**：高（代码路径确凿；「paste 事件在非可编辑焦点可达」依 panel.tsx 注释为开发者实测结论，未真机复验）。

### P1-2 设置页 Esc 无未保存更改保护，且「即时生效 / 保存生效」双模型混用

- **证据**：
  - `src/views/SettingsView.tsx:499-513`：`useEscCapture` 里 `bkDialog` 不存在时直接 `onClose()`，无脏态判断；
  - 延迟保存项：勾选/下拉/热键/捷径/插件开关全部只改本地 `st`，依赖 `saveSettings`（530-583）+ 底部「保存」按钮（1298-1307）落盘；
  - 即时生效项：外观（923-927 `applyAppearance` 立即换肤）、透明效果（951-964 `transparency_set` 注释「即时应用并持久化」）、备份/配置导入导出（动作即时执行）。
- **用户场景与后果**：用户改了保留条数、录了直达热键、加了一条搜索捷径，顺手按 Esc（footer 明示「Esc 清空 / 关闭」是全应用肌肉记忆）→ **全部静默丢弃**，无任何提示。更糟的是外观改了会立即换肤、点保存又会因热键冲突失败而「已保存 ✓」不出现——用户难以建立「什么改了要保存」的心智。捷径增删行（1044-1116）同样即时 UI、延迟落盘。
- **具体建议与权衡**：二选一：①脏标记 + Esc 时弹确认条（复用 `zap-dialog` 确认弹窗，VaultDetailView.tsx:293-319 同款），「放弃更改 / 留在页面」；②统一为即时保存模型（每个控件变更即 `save_settings`，与外观/透明一致），去掉「保存」按钮。推荐 ①：改动小、与现有「热键失败不落盘回拉实际生效值」（574）的严谨性匹配。权衡：确认弹窗多一步，但对「录制热键中途误触 Esc」也是保护。任何方案都不新增键。
- **置信度**：高。

### P1-3 账号库鼠标可达性缺口：vault 行无右键菜单、网址无鼠标「打开」路径

- **证据**：
  - `src/plugins/registry.tsx:114-121`：vault kind 仅有 `activate`（Enter→详情）与 `rowAction`（置顶），**无 `ctxActions`**；`src/App.tsx:1291-1297`：无 ctxActions 的条目右键只压掉默认菜单——vault 行右键是「死右键」（点了毫无反馈）；
  - `src/plugins/vault/VaultDetailView.tsx:174-236`：网址行只有复制按钮，**无「打开」按钮**；「打开网址」唯一入口是 Alt+1（`src/App.tsx:1070`）；
  - 对照： Alt+3 删除有鼠标路径（详情页删除按钮+确认弹窗）、Alt+4 查看有（显示按钮）、Alt+5 置顶有、Alt+6 编辑有——唯独 Alt+1 打开网址没有鼠标等价物。
- **用户场景与后果**：纯鼠标用户（原则声明「其余鼠标」）无法从产品内打开账号网址；只能复制网址行（vault.css:88 `user-select: text` 可选中）再切浏览器粘贴，或记住了 Alt+1。同时 vault 行右键静默无反应，用户会认为右键坏了。
- **具体建议与权衡**：①给 vault kind 加 `ctxActions`（查看密码 / 打开网址 / 编辑 / 置顶 / 删除——动作全部已有后端命令 `vault_action`，右键菜单渲染机制现成）；②详情页网址行尾加「打开」小按钮（与复制按钮并排，`open_item` kind="url" 路径在 `App.tsx:516-525` 已存在）。零新键、全视觉露出。权衡：右键菜单项多一条展开成本，但 vault 行目前连徽标动作都没有，信息密度低，加菜单是净收益。
- **置信度**：高。

### P1-4 合并粘贴模式下点击非剪贴板条目 = 直接启动/打开，模式心智被破坏

- **证据**：
  - `src/App.tsx:929-947`：`runItem` 仅拦截 `mergeMode && it.kind === "clip"`（点选/取消），其余 kind 照常分发——合并模式下点应用行会启动应用、点文件行会打开文件；
  - `src/App.tsx:1443-1451`：底栏「合并粘贴」入口在普通域任何列表状态下常驻显示（与当前列表里有没有 clip 条目无关），`onMouseEnter` 悬停即改 active 的行（`App.tsx:1289`）使误点行更容易。
- **用户场景与后果**：呼出面板（空词列表 = 剪贴板 + 常用应用 + 插件入口混排，`providers/mod.rs:492-504`）→ 点底栏「合并粘贴」→ 行尾出现勾选框（仅 clip 行）→ 用户以为进入「多选模式」，点了一条文件行 → 文件被打开。用户对合并模式建立的是「点=选」预期，其他行无勾选框也无禁用态，破坏由模式引入的心智且产生真实副作用（打开了不想开的东西）。
- **具体建议与权衡**：合并模式下非 clip 条目行降为禁用态（降透明度 + 点击无效 + 空态文案说明「仅文本剪贴板条目可合并」），或进入合并模式时列表自动过滤只留 clip 条目（退出恢复）。后者更干脆，且「过滤」在中转站已有同款实现（`StageView.tsx:78-85`）。权衡：过滤会隐藏上下文（用户可能想确认「哪条是刚复制的」），禁用态保留上下文但多一层视觉噪音。推荐禁用态 + 行首说明。
- **置信度**：高（代码路径确凿；误点概率为推演）。

### P2-5 合并模式下底栏右侧 Esc 提示失真（「Esc 清空 / 关闭」实际是「退出合并」）

- **证据**：`src/App.tsx:1500-1508` 右侧提示无条件渲染 `Esc 清空 / 关闭`；合并模式下 Esc 被窗口捕获接管为 `toggleMerge()`（`App.tsx:833-836`），不再清词/收面板。
- **用户场景与后果**：进入合并模式后按 Esc，预期「清空/关闭」，实际只是退出合并模式；第二次 Esc 才清词。提示与行为不符，虽无破坏性，但违背本项目「footer 提示即契约」的高标准（其余提示全部与行为精确对齐）。
- **建议**：右侧提示随 `mergeMode` 切换为 `Esc 退出合并`（一处三元，零成本）。与发现 4 的禁用态配合后，合并模式的两个入口（底栏按钮、Esc）语义都自洽。
- **置信度**：高。

### P2-6 浅色主题不覆盖落区条与超级面板窗口（推演）

- **证据**：`applyAppearance` 仅在主窗口被调用（`src/App.tsx:224`、`src/views/SettingsView.tsx:926`；`src/lib/appearance.ts:18-31` 挂的是调用方 document 的 documentElement 类）；`src/main.tsx:19-28`：stagedrop / superpanel 两窗口各自独立 WebView 文档，挂载 `StageDropRoot` / `SuperPanelRoot` 时无任何 appearance 应用，恒为 `:root` 深色默认（`tokens.css:7`）。
- **用户场景与后果**：用户选浅色主题 → 面板全白，但拖文件时屏幕角落弹出的落区条与超级面板仍是深色琥珀。「推演」：Tauri 多窗口=多文档，zap-light 类不会跨窗口传染，结论大概率成立；落区条卡面用 `--zap-panel-grad`（stage.css:166）本可跟随浅色，只差挂类。
- **建议**：main.tsx 按窗口 label 挂载时读一次设置并 `applyAppearance`（或后端窗口创建时推送），三窗口主题一致。权衡：极小改动；若刻意保留「落区条恒深色」（类似 imgprev 操作条恒暗玻璃的设计，imgpreview.css:31-35 注释表明暗玻璃是刻意为之），应在设置项描述里写明「落区条恒为深色」，消除「bug 感」。
- **置信度**：中高（代码推演确凿，未真机验证跨窗口 class 隔离）。

### P2-7 Alt+4「查看密码」浮层缺 30s 自动掩码，与详情页「显示」行为不一致

- **证据**：`src/plugins/vault/VaultDetailView.tsx:77-81`：详情页明文展示 30s 自动掩码（注释「屏幕上的明文也要有兜底」）；`src/plugins/vault/VaultRevealOverlay.tsx:23-91`：查看密码浮层明文常驻，无计时器，仅 Esc/按钮关闭。
- **用户场景与后果**：同一产品内两条「看明文密码」路径，一条 30 秒自动遮、一条永不遮。用户从浮层路径看完密码被同事瞥见的暴露窗口无上限（面板失焦即隐可部分兜底，但用户盯着读的场景浮层始终明文）。
- **建议**：浮层复用同一 30s 掩码计时（到时明文变掩码 + 行内提示「已自动隐藏，可再次查看」）。权衡：浮层文案「密码仅本次显示」（VaultRevealOverlay.tsx:53）的语义要同步修正；改后与产品拍板「查看便捷优先」不冲突——30s 后仍可一键再显。
- **置信度**：高（不一致本身确凿；实际风险场景为推演）。

### P2-8 超级面板动作行统一渲染 Copy 图标，非复制类动作语义失真

- **证据**：`src/plugins/super/SuperPanel.tsx:93-97`：每行动尾 `done === a.id ? Check : Copy`——无论动作是换算、搜索还是进主面板，未执行时都显示复制图标。
- **用户场景与后果**：动作清单由后端下发（含搜索/进主面板类），行尾 Copy 图标让用户误以为「点=复制」，与动作实际语义不符；✓ 出现前没有任何「这是搜索动作」的视觉区分。
- **建议**：图标随动作 id 语义分流（搜索用 Search、复制用 Copy、其余用 Sparkles/ArrowRight），或非复制类不渲染行尾图标。权衡：动作清单是后端下发字符串，前端需要一份 id→图标映射（与后端动作清单同源维护）；若嫌耦合，宁可去掉 Copy 只保留 ✓ 执行后反馈。
- **置信度**：高（渲染逻辑确凿；具体动作清单未逐一核对后端 superpanel.rs，图标失真范围以实际清单为准）。

### P2-9 普通域底栏信息密度过高；「合并粘贴」入口在无剪贴板条目时也常驻（推演）

- **证据**：`src/App.tsx:1374-1509`：普通域左侧提示 = ↑↓选择 | Enter启动 | 合并粘贴chip | pw账号库 | Ctrl+V粘贴即识别 | json/tool搜索工具 | 问号，右侧 = Ctrl+,设置 | Esc清空/关闭；`footer.css:20-25` `.zap-footer-hints { flex-wrap: wrap }`。
- **用户场景与后果**：推演 720px 面板宽度下左侧提示大概率换行为两行，footer 变高挤压结果列表（面板固定 480 高，`ctxMenu.ts:6-7`）。且合并按钮与「pw/json/tool」等入口提示混排，视觉权重相同——「合并粘贴」是操作、「pw 账号库」是入口词，语义层级不同却并排。
- **建议**：①底栏做容量预算：窄则隐藏低频提示（json/tool 入口词已有空态文案兜底露出，`App.tsx:1277`）；②「合并粘贴」chip 仅在当前列表含 clip 条目时显示（与发现 4 同根），同时把「合并粘贴」从提示区挪到列表区首个 clip 行附近或作为行内操作，减少模式入口的常驻成本。
- **置信度**：中（换行为推演，需真机确认；常驻显示为代码确凿）。

### P2-10 vault 列表复制成功 = 整列表替换为单行 ✓ + 900ms 收面板，与详情页复制反馈口径不一致

- **证据**：`src/App.tsx:546-557`：`vaultAction` 复制类成功后 `setItems([单行 ✓])` + `setTimeout(hide_panel, 900)`；对照 `VaultDetailView.tsx:123-131`：详情页复制 = toast + 行内 ✓ 点亮，面板不收。
- **用户场景与后果**：自动粘贴关闭的用户（SettingsView.tsx:758-777 该开关可关）在列表里 Alt+2 复制密码后，想再抄用户名——列表已被替换成 ✓ 行、900ms 后面板收起，必须重新呼出重搜。同一「复制」动作在两个页面反馈与停留策略不同，无错误但有学习成本；被替换的瞬间丢失列表上下文。
- **建议**：列表复制改用与详情页同款「行内 ✓ + toast、面板不收」；若保留「复制即走」的启动器心智，至少在自动粘贴关闭时改为不收面板（该设置下用户明确选择了多步操作流）。权衡：收面板防止剪贴板被二次覆盖的意图不明确，行内 ✓ 已有阅后即焚保障（密码不入历史、`pwdClearSecs` 定时焚除），不收面板无安全代价。
- **置信度**：高（行为差异确凿；是否算缺陷取决于「复制即走」是否为刻意拍板——代码注释未说明，见诚实清单）。

## 3. 交互类功能或流程更改建议（≤5 条）

1. **工作台粘贴常驻化**（对应 P0-1）：`useAwaitPaste` 的监听在面板挂载期常驻；「粘贴替换」按钮改为「等待粘贴」状态指示器。使空态文案首次即为真，路径从两步变一步。
2. **账号库补齐鼠标面**（对应 P1-3）：vault 行 `ctxActions`（查看密码/打开网址/编辑/置顶/删除）+ 详情页网址行「打开」按钮。全部复用现有命令与右键菜单机制，零新键。
3. **设置页脏态保护**（对应 P1-2）：脏标记 + Esc 确认条（复用 zap-dialog）；同时给「保存」按钮加禁用态（无更改时置灰），把「哪些改了还没存」可视化。
4. **合并模式作用域收敛**（对应 P1-4/P2-5/P2-9）：进入合并模式即过滤列表只留 clip 条目（或非 clip 行禁用态）；底栏 Esc 提示随模式切换；入口 chip 仅在列表含 clip 条目时显示。
