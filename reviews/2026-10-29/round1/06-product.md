# 06 · 产品维度评审（第一轮 · 2026-10-29）

评审人：产品经理。事实源：磁盘当前状态（含 5 文件在途改动）；对外叙事：README.md。
遵守拍板：砍 AI/快捷命令/OCR、国内双源暂不做、键盘交互原则、密码查看便捷优先、无遥测。本报告无推翻拍板项。

## 1. 角色结论摘要

1. **zap 的功能完成度已到生产级，但「被安装」与「被留住」两侧都是断的**：安装包未签名 + 无 winget/scoop/便携版（第一触点被 SmartScreen 拦截），安装后零首启引导（第二触点靠用户自己发现托盘图标）。这不是功能问题，是漏斗问题。
2. **可发现性设计整体是好的，但有一处结构性死文案**：空面板即功能首页（后端 `fallback_all`，`src-tauri/src/providers/mod.rs:503`）+ 底栏常驻提示（`src/App.tsx:1454`）让 pw/json/tool/中转站都有露出；但空态提示「试试 pw 账号库」（`src/App.tsx:1277`）只在 `items.length === 0` 时渲染（`src/App.tsx:1258`），而空面板恒有插件兜底入口，**新用户几乎永远看不到这条唯一的 pw 文字提示**。
3. **对标六家竞品，功能矩阵上 zap 只缺两块「公共底座」：行内计算器与第三方插件生态**。计算器是 PowerToys Run / Flow / Raycast / Listary（关键词动作）/uTool 都覆盖的输入框型启动器第一高频路径，zap 里 `128*0.75` 会被网页搜索兜底打开浏览器——体验断裂且修复成本低。
4. **反馈回路有模板、无出口**：issue 模板质量高于多数个人项目，但 `zap.log`（`src-tauri/src/providers/diag.rs`）没有任何 UI 出口（设置/托盘均无「打开数据文件夹」），无 panic hook，ErrorBoundary 让用户「见终端日志」（`src/App.tsx:139`）——打包版根本没有终端。无遥测拍板下，用户主动导出诊断是唯一可持续回路，目前缺位。
5. **版本号已失去语义**：14 天发了 13 个版（v0.1.0 2026-10-14 → v0.13.0 2026-10-28，git tag），release notes 是恒定静态文件（`.github/release-notes.md`），无 CHANGELOG。0.x 线性膨胀到 0.50 只是五周后的事，需要现在定义 1.0 的门槛而不是到时候拍脑袋。

## 2. 发现清单（P0 > P1 > P2）

### P0-1 分发信任断层：未签名安装包 + 零替代渠道，漏斗在第一触点收窄
- **证据**：`.github/release-notes.md:3-4` 自己承认「安装包未签名：SmartScreen 可能提示…点更多信息→仍要运行」；`src-tauri/tauri.conf.json:64` 仅 `targets: ["nsis"]`；全仓库 rg 无 winget/scoop/chocolatey 清单（仅 Everything 下载注释提到「官网」）。
- **影响**（用户场景）：一个从聚合文章/朋友推荐来的普通用户下载 setup.exe，Windows 弹「已保护你的电脑」——多数人直接删文件。这不是「介意者自行构建」能覆盖的：签名恰好挡住了最需要低摩擦的那批用户。国内高效工具社区（绿软/scoop 用户）也因为没有便携版而无法接入。
- **建议与权衡**：①提交 winget 社区清单（`winget-pkgs` 仓库，指向 GitHub Releases 的 setup.exe，未签名也可以进 winget）——零成本，一次 PR；②release.yml 追加一个 portable zip 产物（Tauri 主体自包含，WebView2 需检测引导，成本中等）；③代码签名证书（OV 约 ¥1-2k/年）是正解但花钱，可放 1.0 门槛而非立刻。权衡：winget 清单要求版本号稳定可预测，与 P1-6（版本语义）联动。
- **置信度**：高（缺口是仓库事实；SmartScreen 拦截率是产品判断，但 release-notes 自己的警告即是佐证）。

### P0-2 首启引导缺失：安装后用户不知道「按什么呼出」，热键失败也不可见
- **证据**：主窗 `visible: false`（`src-tauri/tauri.conf.json:19`），启动流程（`lib.rs:1780-1926`）只有热键注册/Everything 探测/托盘构建，无任何首启逻辑——rg 全仓 `onboard|welcome|首次|引导` 零命中（仅空态与 css 注释）；托盘 tooltip 是「zap — 个人效率入口」（`lib.rs:1967`），托盘菜单五项（显示面板/设置/剪贴板开关/自启/退出，`lib.rs:1928-1960`）**均不含呼出热键**；呼出热键唯一在产品内的露出是设置页与底栏（进入面板之后才可见）。
- **失败态更糟**：热键注册全部失败时仅 `eprintln!`（`lib.rs:1853-1855`），不落 diag、不改托盘 tooltip、无任何用户可见信号。场景：用户装了另一个占用 Ctrl+Alt+Space 的工具 → zap 「装完没反应」→ 卸载，且给差评。
- **影响**：这是「用户知道按什么吗」的直接答案：不知道。README 的 `Ctrl+Alt+Space` 在 GitHub 上，不在产品里。
- **建议与权衡**：最小改动组合：①首启（settings 表无 `first_run_done` 键即视为首启）自动呼出一次面板；②面板顶部渲染一次性欢迎条（读 `first_run_done`，说明呼出键、pw、右键动作，出现 3 次后落位不再显示——纯前端+一个设置位，不违背键盘原则，无需新组合键）；③热键注册失败时把托盘 tooltip 改为「zap — 热键被占用，请从托盘呼出并到设置修改」+ 落 diag。权衡：欢迎条有「自作主张」风险，控制在 3 次内即可。
- **置信度**：高（缺失是代码事实；「用户找不到热键导致流失」是产品判断，但属启动器品类常识）。

### P1-3 反馈回路有入口无出口：zap.log 无 UI 暴露、无 panic hook、错误指引指向不存在的终端
- **证据**：`diag.rs` 日志轮转 1MB 仅留一代，写入点覆盖焚除/落区条（rg `diag::log` 19 处）；但设置页（`SettingsView.tsx` 分区：启动/剪贴板/中转站/账号库/外观/备份/配置/搜索/网页/插件/更新，rg 分区头验证）与托盘菜单均无「打开数据文件夹/导出诊断」；无 panic hook（rg `panic` 仅 test 断言）；ErrorBoundary 文案「完整信息见终端日志」（`src/App.tsx:139`）——NSIS 打包版无终端，这条指引对最需要它的人无效。
- **影响**：无遥测拍板下，远程诊断完全依赖用户主动提交材料。现在用户连 `zap.log` 存在于 `%APPDATA%\com.ais.zap\` 都无从得知（README 数据存储节有，但 Again：README 在 GitHub）。线上事故 = 只能靠用户口述复现。
- **建议**：设置加一行「打开数据文件夹」（`explorer %APPDATA%\com.ais.zap`，一条命令）；`main.rs` 挂 panic hook 落 diag；ErrorBoundary 文案改为指向该路径；bug_report.yml 增加一项「如可能，附 `%APPDATA%\com.ais.zap\zap.log`（已提醒抹隐私）」。
- **置信度**：高。

### P1-4 行内计算器缺失：输入框型启动器的公共底座，四/五家竞品标配
- **证据**：rg `calculat|计算器|单位换算` 仅命中 Windows 计算器应用条目（`providers/apps.rs:391`）；`SearchEngine::search`（`providers/mod.rs:492-521`）对非识别内容走网页兜底（web 恒有产出）。
- **影响**（用户场景）：呼出 → 输入 `128*0.75` → Enter → **浏览器打开百度搜「128*0.75」**。这是 Raycast/PowerToys Run/Flow/Wox 用户每天数十次的路径（算数→复制结果），zap 在此处主动把用户推出面板。对比：JSON/时间戳/Base64 识别（probe 机制，`mod.rs:583`）已建好同类骨架，计算器是同一模式的第二个消费者。
- **建议**：新增 `calculator` 纯函数模块 + probe 挂钩（安全表达式解析，禁函数调用，四则/括号/百分比起步），结果条目 Enter=复制。不违背任何拍板（非 AI/快捷命令/OCR；键盘面 Enter 即可）。工作量：解析器+测试约一天级。
- **置信度**：高（缺口可证；「高频」是产品判断，有竞品标配佐证）。

### P1-5 「面板打不开」类工单不可远程定位：直达热键失败同样静默
- **证据**：呼出热键失败仅 eprintln（`lib.rs:1853-1855`）；四槽直达热键失败 `eprintln!`（`lib.rs:1884`）注释自己写「注册失败仅落日志不影响启动」但落的是 stderr 不是 diag。设置页保存时可实时试注册报错（README:71），但**启动时静默失败**场景（占用方后启动、组策略禁全局热键）无覆盖。
- **影响**：与 P0-2 的失败态合并看：用户视角是「zap 坏了」，开发者视角是零信号。此类工单在 issue 里无法复现（环境相关）。
- **建议**：两处 `eprintln` 改 `diag::log`（一处改动，立即让 zap.log 具备定位「热键失灵」能力）；托盘 tooltip 动态化见 P0-2 建议③。
- **置信度**：高。

### P1-6 版本语义空心化：14 天 13 版，release notes 恒定，无 CHANGELOG
- **证据**：git tag v0.1.0（2026-10-14）→ v0.13.0（2026-10-28），每日 +0.1；`.github/release-notes.md` 全量 1 段静态文案，release.yml:92 每个 tag 复用同一文件；仓库无 CHANGELOG.md。
- **影响**：用户视角「0.12 → 0.13 更了什么」无答案——更新提示（`useUpdater`，设置页可见）弹出后，用户没有「这次更了啥、要不要更」的决策材料。同时版本号按日历速度冲向 0.50，会先于产品成熟耗尽 0.x 空间。设置→自动更新是产品内最频繁的「产品-用户对话」时刻，当前它是最沉默的。
- **建议**：①仓库根加 CHANGELOG.md（Keep a Changelog 格式，已知 13 版可回补——git log 的 commit message 信息量足够提取）；②release.yml 生成 per-tag notes（tag message 或 CHANGELOG 对应段落）；③版本节奏改「功能攒批 + 语义化 patch/minor」，不追求日更。
- **置信度**：高。

### P2-7 超级面板是孤岛：默认未绑定，面板/托盘/空态零露出
- **证据**：默认空串未绑定（`SettingsView.tsx:75`「超级面板直达热键（空串 = 未绑定）」，README:60「默认未绑定」）；rg 全产品面（空态 `App.tsx:1277`、底栏 `App.tsx:1454-1465`、托盘菜单 `lib.rs:1928-1960`）均无超级面板提示，唯一入口是 设置→启动（`SettingsView.tsx:668`）。
- **影响**：超级面板是拍板保留的 uTool 对标功能，但「选中内容→按热键」的前提是先到设置里绑键并理解「热键与呼出同机制」。实际结果：功能存在、无人发现，与「砍掉」在用户行为上等价。
- **建议**：不动键盘原则（不预绑热键——热键占用风险与拍板精神都不允许），但把它从「设置里的一行」提升为「欢迎条/设置首屏的一张卡片：『超级面板：绑定热键后，选中文字按热键即出动作菜单』+ 绑定按钮」。若欢迎条方案采纳（P0-2），放第三张卡即可。
- **置信度**：高（露出缺失是代码事实；「无人发现」是产品推断）。

### P2-8 空态死文案：「试试 pw 账号库」在新用户路径上永不渲染
- **证据**：空态分支条件 `items.length === 0`（`App.tsx:1258`）；空查询时后端返回 最近剪贴板 + top4 启动应用 + 插件兜底入口（`mod.rs:494-504`），兜底至少含 JSON/文本工具/中转站三条（`mod.rs:197-209` 注册序，`stage.rs:522-527`、`jsontools.rs:58`、`texttools.rs:56`）。因此新装用户首呼出看到 3+ 条，`App.tsx:1277` 的提示不可达。
- **影响**：这条文案是 pw 之外唯一「文字面」引导，写得好但挂在永不成立的分支上。pw 实际靠底栏常驻提示（`App.tsx:1454`）撑住——能发现，但提示语写了两遍其中一遍白写。
- **建议**：空态判断改为「首启前 N 次呼出」或删掉该行并入 P0-2 欢迎条；也可把空态改为只在「所有插件停用且无历史」的极端分支出现。低成本修一致性。
- **置信度**：高（渲染条件与后端返回均可代码验证）。

### P2-9 第三方插件生态缺失：对标产品的长期差距，1.0 可延后但需路线声明
- **证据**：插件体系是编译期内置注册表（`mod.rs:197-209`）+ 声明化入口（`plugin.rs:74`）+ panel.ts 面板契约（`src/plugins/panel.tsx`），无任何加载外部插件代码（rg 无 dlopen/动态加载；这是安全性优点也是生态上限）。
- **影响**：uTool/Flow Launcher/Raycast 的护城河是商店生态；zap 对它们的替代性当前止步于「内置功能覆盖」。个人开发者自建商店不现实，但「插件体系只服务内置」意味着可发现性投人的每一个插件（如未来计算器）都要自己写。
- **建议**：1.0 不做外部插件（维持安全边界），但在 README/路线声明一句话立场（「插件体系面向内置，外部插件暂不在路线图」或「预计以受信任清单形式开放」），避免被对标产品用户默认对比。
- **置信度**：中（生态缺失是事实；「需要声明」是策略判断）。

### P2-10 文档漂移：三处数字/引用过时
- **证据**：README:132「cargo test（113 个）」vs 最新 commit 自述 Rust 117→118（git log ad99093）——README 已落后两笔；`SECURITY.md:14` 引用「设置 → 关于」，设置页实际无「关于」分区（版本号在「软件更新」区，`SettingsView.tsx:1196-1203`）；`bug_report.yml:14` 版本占位符 `"0.1.0"`。
- **影响**：单条都是小事，但都出现在「用户按文档办事」的路径上（报 bug 填版本、按 SECURITY 交报告）。个人项目最常见的信任损耗点是「文档说 A 界面是 B」。
- **建议**：测试数改为「117+」或删除具体数字（会漂移的数字不进 README）；SECURITY.md 改「设置 → 软件更新区可见版本号」；占位符改 "0.13.0"。
- **置信度**：高。

## 3. 功能新增或流程更改建议（≤5 条，按 ROI 排序）

1. **行内计算器**（P1-4）：probe 挂钩 + 纯函数解析器 + 测试。唯一新增功能，理由是竞品公共底座 + 现有 probe 骨架近零边际成本 + 不触碰任何拍板。
2. **首启引导三件套**（P0-2/P2-7/P2-8 合并交付）：`first_run_done` 设置位 → 首启自动呼出；欢迎条出现至多 3 次（呼出键/pw/右键动作/超级面板绑卡各一张）；热键注册失败时托盘 tooltip 动态告警。全程不新增组合键。
3. **诊断出口**（P1-3/P1-5 合并）：设置「打开数据文件夹」按钮 + panic hook 落 diag + 两处 eprintln 改 diag + bug 模板加日志附件项。这是无遥测拍板下反馈回路的唯一正解。
4. **分发动作**（P0-1）：winget 社区清单 PR + release.yml 追加 portable zip。流程更改，不动产品代码。
5. **CHANGELOG 与 1.0 门槛成文**（P1-6）：CHANGELOG.md 回补 13 版；把 1.0 门槛写成一条 issue 挂仓库（建议门槛：①分发可信达成其一——签名或 winget+便携 ②首启引导上线 ③诊断出口上线 ④CHANGELOG 机制运转 ⑤更新链路完成一次真实端到端灰度含签名验证 ⑥当前功能面稳定一个迭代周期无行为翻转）。何时 1.0 = 门槛全绿时，不设日期。

## 4. 诚实清单

- **竞品矩阵基于公开产品知识（产品判断）**，未逐一安装 2026-10 时点的最新版本比对；PowerToys Run/Flow 的插件清单以历史认知为准，个别插件可能新增/下架。Wox「基本停止维护」为社区共识级判断，未做最近活跃度核查。
- **GitHub Discussions 是否开启**无法从磁盘验证（属仓库设置）；本报告按「无 Discussions 引用」计。
- **NSIS 安装器默认勾选「安装后运行」**基于 Tauri 默认模板行为（产品判断），未实装 setup.exe 验证首启路径；若不成立，P0-2 的紧迫度更高。
- **Ctrl+Alt+Space 冲突率**未实测（产品判断：与主流输入法/IM 冲突概率低但非零）；「热键被占用导致流失」无数据支撑，仅按品类常识推断。
- **vault 的 Alt+1~6**（README:108，悬停提示 `App.tsx:90`）与拍板「不新增需记忆组合键」存在张力——按存量功能处理（有 hover 说明、非本轮新增），未计为发现；若未来扩展类似面需注意原则一致性。
- **README 测试数漂移的「实际值」**取自 git commit message 自述（118），未跑 `cargo test` 复核。
- **「SmartScreen 拦截率」**无量化数据；P0-1 的定性依据是 release-notes 自己的警告与 winget 未接入的渠道事实。
- 未审查中文文案的错别字/术语一致性（超出本轮范围，文案整体质量高）。
